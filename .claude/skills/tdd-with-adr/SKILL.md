# t-wada流TDD + ADR開発ガイド

## 基本原則

### TDDサイクル（Red → Green → Refactor）

1. **Red**: 失敗するテストを先に書く（型エラーもRedとみなす）
2. **Green**: 最短距離でテストを通す（仮実装→明白な実装）
3. **Refactor**: 重複除去・命名改善・意図の明確化

### ベイビーステップ

- テストも実装も極小に保つ
- 1つのテストは1つの意図のみ
- 「同じことを3回書いたらDRY」

## 開発ワークフロー

### フェーズ1: 調査

1. 実装対象の要件を明確化
2. 既存コードのパターンを確認
3. テスト対象のインターフェースを特定

### フェーズ2: 計画

1. テストケースをリストアップ（最小から最大へ）
2. 境界値・エッジケースを特定
3. モック/フェイクが必要な箇所を把握

### フェーズ3: 実装（TDDサイクル）

各テストケースに対して：

```
進捗チェックリスト:
- [ ] テストを書く（Red確認）
- [ ] 最短で実装（Green確認）
- [ ] リファクタリング（テスト通過確認）
```

**テスト実行コマンド**: `npm run test:comp`

各フェーズ後に必ずテストを実行し、期待通りの結果を確認する。

### フェーズ4: 検証

1. 全テスト通過を確認: `npm run test:comp`
2. 型チェック: `npm run tsc`
3. リンター: `npm run biome:check`
4. 一括確認: `npm run check`

### フェーズ5: ドキュメント（ADR作成判断）

以下の場合にADRを作成：

- 技術・ライブラリの選定
- アーキテクチャパターンの採用
- トレードオフのある設計判断
- 既知の制約・技術的負債

ADRが必要な場合は [ADR-TEMPLATE.md](ADR-TEMPLATE.md) を参照。

## テスト設計指針

### 構造

```typescript
test("振る舞いを日本語で記述", async () => {
  // Arrange: 準備
  // Act: 実行
  // Assert: 検証
});
```

### React コンポーネント

- React Testing Libraryでユーザ視点の検証
- `TSQWrapper`でQueryClientをラップ
- MSWでSupabase APIをモック

### ユーティリティ/サーバー

- 入出力中心の純粋関数テストを優先
- 外部I/Oは境界で抽象化し、モック注入

## 禁止事項

- テストなしの実装追加
- 複数の意図を1つのテストに詰め込む
- Greenを壊す大規模リファクタリング
- 外部サービス直叩きのユニットテスト
