# ADR作成ガイド

## テンプレート

```markdown
# XXXX. タイトル

日付: YYYY-MM-DD

## ステータス

Proposed | Accepted | Deprecated | Superseded by [XXXX](./XXXX-xxx.md)

## コンテキスト

なぜこの決定が必要になったのか。背景と問題を説明。

## 決定

何を決定したのか。具体的な内容を記述。

## 理由

なぜこの決定をしたのか。根拠を列挙。

## 結果

### 良い影響

- 期待されるメリット

### 悪い影響・トレードオフ

- 予想されるデメリットや制約

## 代替案

検討した他の選択肢とその却下理由。

## 関連する決定

関連するADRへのリンク（あれば）。

## 参考

参考にした資料やリンク。
```

## 命名規則

```
docs/adr/XXXX-short-descriptive-title.md
```

- `XXXX`: 4桁の連番（0001, 0002, ...）
- `short-descriptive-title`: ケバブケースの簡潔なタイトル

## 次の番号を取得

```bash
ls docs/adr/*.md | grep -E '[0-9]{4}' | sort | tail -1
```

## ADR作成が必要なケース

- 技術スタック・ライブラリの選定
- アーキテクチャパターンの採用
- データモデルの重要な設計判断
- パフォーマンスと可読性などのトレードオフ
- 既知の制約や技術的負債の記録
